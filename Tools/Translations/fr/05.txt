Chaque valeur est substituée partout où {name} apparaît dans une condition ou une action, branches comprises : par ex. Location_{char} comme nom de variable, ou {char}/Slot comme chemin de GameObject. Cela se combine avec le reste de la syntaxe – $Prefix_{char} lit la variable propre à chaque valeur. Chaque valeur a son propre état de front et ses propres échéances de Timer, pour que les valeurs se comportent exactement comme les règles séparées qu'elles remplacent (cochez 'stagger' sur un Timer pour étaler leur premier déclenchement). Laissez vide pour exécuter la règle une fois.
integration.eachValue = Pour chaque valeur de :
integration.placeholderName = Nom du paramètre fictif :
integration.editingMode = Mode d'édition
integration.codeModeEditConditions = Mode code (éditer conditions + actions en JSON)
integration.pickerModePickAction = Mode sélecteur = choisir dans les catalogues d'actions / de conditions ligne par ligne. Mode code = écrire le corps de la règle directement en JSON. Mêmes données, deux vues.
integration.ruleConditions = Conditions (toutes doivent être remplies)
integration.addIntegrationCondition = + Condition
integration.addIntegrationConditionGroup = + Groupe
integration.copyConditions = Tout copier
integration.pasteConditions = Coller
integration.overwriteConditions = Remplacer
integration.ruleActionsBox = Actions (lancées quand les conditions se déclenchent)
integration.addIntegrationAction = + Action
integration.elseIfBranchesFirst = Branches sinon-si (la première qui correspond l'emporte)
integration.addBranch = + Branche sinon-si
integration.ifRuleSMain = Si les conditions principales de la règle échouent, ces branches sont essayées de haut en bas et la PREMIÈRE dont les conditions sont remplies lance ses actions. Les modes de déclenchement sur front se déclenchent chaque fois que la branche gagnante change – idéal pour des cascades de type planning (si créneau A → …, sinon si créneau B → …, sinon → …).
